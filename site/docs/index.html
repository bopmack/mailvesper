API reference

Send email through your own Amazon SES account, keep contacts in sync, feed events to your journeys and get signed notifications for everything that happens to a message.

Every request goes to this base URL over HTTPS, with JSON bodies:

https://mail.example.com/api/v1

Before you send, connect Amazon SES (or your own SMTP server) and verify a sender in the app. Each response carries an X-Request-Id header; send your own (8–64 letters, digits or hyphens) to have it echoed back, which helps when you contact support.

Authentication

Create a key under API keys (owners and admins). It is shown once; MailVesper keeps only a hash. Send it as a bearer token:

Authorization: Bearer sl_live_…

Keys belong to one workspace and have one of two scopes:

ScopeCan call
sendSending and reading emails: /emails, /emails/batch, /emails/{id}.
fullEverything above, plus /contacts, /events and /webhooks.

A missing or malformed key returns 401 unauthenticated; a revoked key the same. A send key on a contacts or events route returns 403 forbidden.

Errors always use the same JSON shape. fields, retry_after and details appear only when they apply.

Rate limits

Each API key can make 600 requests a minute, across all endpoints. Journey trigger URLs allow 600 a minute per journey and 300 a minute per sending IP. Over the limit you get 429 rate_limited with a Retry-After header.

This is separate from Amazon SES’s own sending rate: MailVesper queues accepted emails and paces them to your SES quota, so a burst of API calls doesn’t fail because SES is slower.

Idempotency

POST /emails and POST /emails/batch accept an Idempotency-Key header (8–255 characters). Retry with the same key after a timeout and you get the first response back, with Idempotent-Replayed: true, instead of a second email.

  • Keys are remembered for 24 hours, per workspace. Only successful responses are stored.
  • The same key with a different body returns 409 idempotency_conflict.
  • While the first request is still running, a repeat returns 409 request_in_progress.
Idempotency-Key: order-1042-receipt

Send an email send

POST/emails

Creates one message per recipient and returns 202 right away; sending happens in the background, paced to your SES quota.

Send a batch send

POST/emails/batch

Different emails in one request: the body is a JSON array of up to 100 email objects, each with the fields of Send an email, reaching at most 500 recipients in total. It’s all or nothing: if any item is invalid, nothing is sent and the error fields are prefixed with the item’s index ("3.to").

curl -X POST https://mail.example.com/api/v1/emails/batch \
  -H "Authorization: Bearer $MAILVESPER_KEY" \
  -H "Content-Type: application/json" \
  -d '[
    { "from": "Acme <orders@acme.com>", "to": "amara@example.com", "subject": "Order 1042 shipped", "text": "On its way." },
    { "from": "Acme <orders@acme.com>", "to": "tunde@example.com", "subject": "Order 1043 shipped", "text": "On its way." }
  ]'

The response is the same as for a single send, with one batch_id shared by every message.

Merge tags

Subjects, HTML and text can use {{ name }}, with an optional fallback: {{ first_name | there }}. Values are HTML-escaped in the HTML body and left as they are in the subject and text.

Values come from, in order (the first one found wins):

  • the request’s variables (in a journey: the properties of the event that started it, so a journey on tip_sent can say “Thanks for the {{ amount }} tip”);
  • the recipient’s contact, if they are one: first_name, last_name, email and every custom field;
  • built-ins: email, tracking_code, unsubscribe_url, preferences_url, web_version_url.

Using {{ unsubscribe_url }} or {{ preferences_url }} in a body adds unsubscribe headers even to transactional email.

Bulk create or update full

POST/contacts/batch

For syncing an existing user base: the body is a JSON array of up to 500 contacts, each with the fields of Create or update. Every item is checked before anything is saved (error fields are prefixed with the index, e.g. "12.email"). An email that appears twice is saved once, with its last values. On installations with plan limits, the new contacts must fit as a whole or nothing is saved (402 plan_limit).

curl -X POST https://mail.example.com/api/v1/contacts/batch \
  -H "Authorization: Bearer $MAILVESPER_KEY" \
  -H "Content-Type: application/json" \
  -d '[
    { "email": "amara@example.com", "fields": { "total_spent": 120.5, "is_creator": false } },
    { "email": "tunde@example.com", "first_name": "Tunde", "tags": ["vip"] }
  ]'
{
  "data": [
    { "email": "amara@example.com", "id": "01jbz9…", "status": "updated" },
    { "email": "tunde@example.com", "id": "01jbza…", "status": "created" }
  ],
  "created": 1,
  "updated": 1
}

A custom field seen for the first time is added to your fields with a type taken from its value: numbers become number, true/false true/false, 2026-10-26-style values date, everything else text. That’s what lets you build segments like “total spent is more than 100”. A field’s type never changes afterwards.

Erase a contact full

DELETE/contacts/{email}

For data-deletion requests. The contact is deleted; on their past emails the address is replaced with an anonymous one and the subject and body are removed. The address is added to the suppression list so it is never emailed again. Returns {"erased": true}.

This can’t be undone. To stop email without erasing history, send "unsubscribed": true instead.

Delivery and retries

  • Answer with any 2xx within 10 seconds. Redirects aren’t followed.
  • Anything else is retried after 1 minute, 5 minutes, 30 minutes, 2 hours, 6 hours and 12 hours (7 attempts over about 20 hours), then marked failed.
  • After 50 failures in a row with no success for a day, the endpoint is paused and the app says why. Turn it back on once it’s fixed.
  • Events can arrive more than once or out of order. Use the webhook-id header to skip repeats.
  • Endpoints must be public https:// URLs on port 443 or 8443, without a username or password in the URL. Private and internal addresses are refused.

Verifying signatures

Every webhook is signed using the Standard Webhooks scheme, so you can also use their libraries. Three headers come with each request:

webhook-id: msg_01jbza…
webhook-timestamp: 1793011205
webhook-signature: v1,K5oZfzN95Z9UVu1EsfQmfVNQhnkZ2pj9o9NDN/H/pI4=

The signature is base64(HMAC-SHA256(key, "{webhook-id}.{webhook-timestamp}.{body}")), where key is your endpoint’s secret without the whsec_ prefix, base64-decoded. Find the secret on the endpoint in the app. Always check the raw body before parsing it, and reject old timestamps to stop replays.

import crypto from 'node:crypto';

// headers: the request headers; rawBody: the body exactly as received (a string).
export function verifyMailVesper(secret, headers, rawBody) {
  const id = headers['webhook-id'], timestamp = headers['webhook-timestamp'], signatures = headers['webhook-signature'] || '';
  if (!id || !timestamp || Math.abs(Date.now() / 1000 - Number(timestamp)) > 300) return false; // older than 5 minutes: reject
  const key = Buffer.from(secret.replace(/^whsec_/, ''), 'base64');
  const expected = Buffer.from(crypto.createHmac('sha256', key).update(`${id}.${timestamp}.${rawBody}`).digest('base64'));
  return signatures.split(' ').some((s) => {
    const [version, sig] = s.split(',');
    const given = Buffer.from(sig || '');
    return version === 'v1' && given.length === expected.length && crypto.timingSafeEqual(given, expected);
  });
}
// $headers: lower-case header names; $rawBody: file_get_contents('php://input').
function verify_sendline(string $secret, array $headers, string $rawBody): bool
{
    $id = $headers['webhook-id'] ?? '';
    $timestamp = $headers['webhook-timestamp'] ?? '';
    if ($id === '' || ! ctype_digit($timestamp) || abs(time() - (int) $timestamp) > 300) {
        return false; // older than 5 minutes: reject
    }
    $key = base64_decode(preg_replace('/^whsec_/', '', $secret));
    $expected = base64_encode(hash_hmac('sha256', "$id.$timestamp.$rawBody", $key, true));
    foreach (explode(' ', $headers['webhook-signature'] ?? '') as $part) {
        [$version, $sig] = array_pad(explode(',', $part, 2), 2, '');
        if ($version === 'v1' && hash_equals($expected, $sig)) {
            return true;
        }
    }

    return false;
}

Rotating the secret in the app takes effect for the next delivery.

Journey webhooks

A journey’s Send webhook step POSTs the contact and what started the journey to your URL. It’s signed the same way as event webhooks, with the journey’s own secret: owners and admins can reveal it on the step in the journey editor.

{
  "type": "journey.step",
  "journey": { "id": "01jbzb…", "name": "Welcome series" },
  "run_id": "01jbzc…",
  "contact": { "id": "01jbz9…", "email": "amara@example.com", "first_name": "Amara", "fields": { "plan": "pro" }, … },
  "trigger": { "event": "order_placed", "properties": { "order_id": "1042" } },
  "sent_at": "2026-10-26T10:30:00Z"
}

The User-Agent is MailVesper-Journeys/1.0. Answer with a 2xx within 10 seconds; the step isn’t retried, and the journey records it as sent or failed and moves on. The same URL rules apply as for event webhooks.

Unsubscribe headers

Marketing email, email with a topic, and email with "unsubscribe": true get the headers Gmail and Yahoo require of bulk senders (RFC 8058 one-click):

List-Unsubscribe: <https://mail.example.com/api/v1/unsubscribe/…>
List-Unsubscribe-Post: List-Unsubscribe=One-Click

Unsubscribes take effect immediately: the address joins your suppression list, marketing stops (transactional email still arrives), and an email.unsubscribed webhook is sent. {{ unsubscribe_url }} links to a page where people can unsubscribe or, if you use topics, choose what they still want.
